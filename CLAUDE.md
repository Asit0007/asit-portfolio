# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A 3D driving-game portfolio for Asit Minz (Cloud & Infrastructure Engineer, Bangalore). The visitor drives a car through a desert world where each named zone is a resume section; there's also a racing circuit with a global leaderboard, a bowling mini-game, visitor-left comments placed in the world, and a live visitor counter. Heavily inspired by folio-2025 (Bruno Simon-style portfolio) — several in-code comments reference "folio" for design decisions.

**There are two front doors, and both matter.** `StartScreen.jsx` offers **GG MODE** (the 3D world) and **OG MODE** (a written, scrollable résumé — experience, projects, skills, contact, CV download). OG MODE is not a fallback page bolted on the side: it lives in `StartScreen.jsx` (which is why that file is ~960 lines), it is reachable from the boot screen *and* from `PerfNotice` when a device can't render the world, and `store.showResume` is what both routes set. When it's open the Canvas drops to `frameloop="demand"` — someone reading the résumé because the 3D was too slow for their machine should not still be paying for the 3D. Anything that changes résumé content has to change it in **both** places: `ZONES` in the store for the world, and the OG MODE markup.

Stack: React 18 + Vite 6, Three.js via @react-three/fiber (R3F) + drei, physics via @react-three/rapier (Rapier WASM), Zustand for state, Howler for audio. **No CSS framework** — Tailwind was removed (see history below); styling is inline styles plus `src/index.css`, which holds the resets and the self-hosted JetBrains Mono `@font-face`. Every `fontFamily` in the app must go through the `--font-mono` custom property defined there, never a bare `monospace`. Backend is Vercel serverless functions (`api/`) + Upstash Redis. Deployed on Vercel (project `asit-portfolio`, linked in `.vercel/project.json`).

**Before any visual, UI, motion, or audio work, read `DESIGN.md`** — the design system extracted from folio-2025's source, with this project's own token values and non-negotiable UX rules (never interrupt driving, graceful offline states, typing guard, mobile parity, draw-call budgets).

## Commands

```bash

npm run build     # production build → dist/
npm run preview   # preview production build
npm run lint      # eslint over src/ and api/ (flat config at eslint.config.js)
```

Lint policy: `catch (_) {}` and empty catch blocks are allowed by config — they're the codebase's graceful-degradation contract, not oversights. The react-hooks compiler rules (`set-state-in-effect`, `immutability`, `refs`) and `react-refresh/only-export-components` are demoted to warnings because they flag long-standing working patterns; keep the error count at zero.

There are no tests. Local dev has no Redis credentials by default, so leaderboard/comments/visitor APIs return null and the UI shows its offline states — that's expected. To exercise the API routes locally you need `vercel dev` plus `vercel env pull` (requires `vercel login`; the CLI in dependencies is v32).

## Big-picture architecture

### Two render worlds, one store

`App.jsx` is the DOM shell: it mounts `<KeyboardControls>` → `<Canvas>` → `Scene.jsx` (everything 3D), and, alongside the canvas, the 2D HUD/overlay components. **`Scene` is `React.lazy`-loaded** (inside a `<Suspense fallback={null}>` within the Canvas): Scene is the only import path to `@react-three/rapier`, so the ~2 MB rapier chunk stays out of the initial bundle and streams in behind the start screen — don't statically import Scene (or anything that imports rapier) from App/main, or the split silently collapses. The remaining 2D components (`ZoneOverlay`, `LapTimerHUD`, `AchievementSystem`, `WhisperInput`, `NosHUD`, `MapOverlay`, `MusicPlayer`, `MobileControls`, `StartScreen`). **Mobile portrait is forced into landscape**: `useForcedLandscape` in `App.jsx` wraps the whole app in a CSS-rotated frame (`rotate(90deg)`, sized `100dvh × 100dvw`, animated flip intro). The frame's transform makes it the containing block for every `position:fixed` overlay, so all UI lays out in the rotated space untouched; the Canvas needs `resize={{ offsetSize: true }}` so R3F measures layout size, not the (portrait) bounding rect — pointer picking stays correct because R3F divides local-space `offsetX/Y` by that size. The two worlds communicate through:

1. **`src/store/useGameStore.js` (Zustand)** — the single state hub. Holds zone state, game lifecycle (`gameStarted`), mobile joystick state, race state machine (`raceState: idle|racing|finished`), best/last lap, `pendingLeaderboardSubmit`, achievements (`visitedZones`, `strikeCount`), comment state (`whisperInputOpen`, `whispers`), and the vehicle's Rapier body handle (`vehicleBody`). Several components write directly via `useGameStore.setState(...)` rather than through actions — that's an established pattern here, not an accident.
   - The store also exports `ZONES`: **this object is the resume content** (experience, projects, contact info). Edit resume text there, not in components.

2. **`window.__*` globals for per-frame values** — values that change every frame are deliberately NOT routed through Zustand (would re-render React every frame). Current globals: `__carPosition` (written by `Whispers.jsx`), `__nosLevel` / `__isBoosting` (written by `Vehicle.jsx`, read by `NosHUD` and the animated `document.title`), `__raceElapsedMs` (written by `Circuit.jsx`, polled by `LapTimerHUD` on a 50 ms interval), `__resetCar` (set by App's R-key handler, consumed in `Vehicle.jsx`'s frame loop), `__mobileSteer` (analog -1..1 steering written by `MobileControls.jsx`'s wheel on every touchmove, read by `Vehicle.getInput()` — deliberately not in `store.joystick` because Scene subscribes to `joystick` and would re-render the 3D tree per move). Note: the store has `needsReset`/`resetCar` intended to replace `__resetCar`, but the global is still what's actually wired up.

### Input

Two parallel input paths, and both must respect text fields:
- **drei `KeyboardControls`** (`src/Controls.js` keyMap: WASD/arrows, Space brake, Shift boost) polled via `getKeys()` in `Vehicle.jsx`. On mobile, a cockpit layer (`MobileControls.jsx`): gas/brake pedals + boost write press/release booleans into `store.joystick` (OR-merged with keys in `Vehicle.getInput()`; the brake pedal maps to `backward` — Vehicle brakes to a stop before reversing, correct two-pedal behavior), and the steering wheel writes analog steer to `window.__mobileSteer` (see globals above). Steering is analog end-to-end: `getInput()` returns `steer` (-1..1, +1 = left), priority keyboard → wheel → legacy joystick booleans.
- **A global `keydown` listener in `App.jsx`**: R = reset car, M = music toggle, C = open comment input, Tab = map.

**Typing guard (do not regress):** both `App.jsx`'s keydown handler and `Vehicle.jsx`'s `getInput()` bail out when `document.activeElement` / `e.target` is an INPUT/TEXTAREA/contentEditable. Without this, typing in the comment box or leaderboard name field resets the car (R), reopens the comment box (C), and drives/brakes the car (WASD/Space). Any new global hotkey or input consumer must keep this guard.

### Vehicle physics (`Vehicle.jsx`)

Rapier **raycast vehicle controller** (`world.createVehicleController`) on a chassis RigidBody — 4 wheels, front pair steered, rear pair driven (RWD). Gravity is `[0,-20,0]` (2× real). The file's top constants are the tuning surface (engine/brake forces, suspension, friction slip) and the comments there explain non-obvious choices: anisotropic inertia override (high pitch inertia to prevent wheelies/stoppies), soft speed cap via force attenuation, moderate grip to prevent roll-overs, and a chassis collider deliberately kept above the wheels' contact patch. **The car faces −Z**; the GLB model (`/public/models/car-1.glb`) is rotated `Math.PI` to match, and `FORWARD_SIGN` exists to flip drive direction if the wheel setup changes. Camera is a speed-zooming follow-cam in the same `useFrame`, with a brief decaying "establishing" bias when entering a zone. A `BoxCar` procedural fallback renders while the GLB loads (`HAS_GLTF` flag).

Other components never touch the controller — they read `translation()`/`linvel()` off the chassis body from the store or a passed ref.

### Racing circuit & leaderboard flow

`src/data/track.js` is the **single source of truth** for circuit geometry: 9 checkpoints on a big wraparound loop, path widths, radii. The checkpoint coordinates were verified against every world hazard with clearance margins — checkpoint 5 looks redundant but is load-bearing for the curve shape (see comments there). `Circuit.jsx` builds the visual track procedurally (merged geometry, checkered borders) and runs the race: sequential checkpoint hits → lap time → `raceStorage.js` localStorage best (`circuitBestLapMsV2`) → on a new local best, sets `store.pendingLeaderboardSubmit` → `LapTimerHUD` prompts for a name and POSTs to `/api/leaderboard`.

**Versioning rule:** the Redis leaderboard key (`circuit-leaderboard-v2` in `api/leaderboard.js`) and the localStorage best-lap key (`circuitBestLapMsV2` in `raceStorage.js`) are bumped **together** whenever the track shape/length changes, so old times aren't compared against a different track.

### Backend (`api/` + Upstash Redis)

Three Vercel serverless functions, all following the same shape: `Redis.fromEnv()` constructed lazily inside the handler → returns **503** if env vars are missing, try/catch around everything.
- `api/leaderboard.js` — sorted set `circuit-leaderboard-v2`, keeps fastest 100, returns top 10. Light validation only (12-char name, time bounds), no real anti-cheat.
- `api/whispers.js` — list `whispers`, capped at 30 newest, 30-char messages with world x/z position.
- `api/visitors.js` — counter `total-visitors`, INCR'd once per browser (deduped client-side via localStorage).

`Redis.fromEnv()` accepts either `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN` or `KV_REST_API_URL`/`KV_REST_API_TOKEN` — covering both naming schemes the Vercel/Upstash integration may inject. **These env vars must be set in the Vercel project for the leaderboard/comments/visitor counter to work in production**; without them every function 503s and the UI shows OFFLINE.

Client-side counterparts in `src/utils/*Api.js` resolve to `null` on ANY failure so the UI degrades gracefully (OFFLINE label, silent no-op) instead of erroring. Keep that contract.

### The "Comments" feature (internally: whispers)

Visitor-left messages placed at the car's position in the world. **User-facing copy says "comment"; all internal names remain "whisper"** (`Whispers.jsx`, `whisperApi.js`, `whisperStorage.js`, `/api/whispers`, store fields, Redis key). Do not rename the internals — the Redis key and localStorage key (`hasWhispered`) hold live production data. `Whispers.jsx` exports two components: `Whispers` (inside Canvas — markers + writes `__carPosition`) and `WhisperInput` (outside Canvas — the text box, opened with C). One comment per browser, enforced via localStorage only.

### Performance tiers (`src/hooks/usePerformance.js`)

Mobile UA → tier 0 (settled in the initial state, at mount — the tier feeds fog and resolution, so resolving it late made the world visibly change on START); otherwise ~90 frames of FPS measurement → tier 0/1/2. A watchdog keeps sampling and only ever steps **down**. `TIER_CONFIG` drives tree/prop counts, resolution, fog distance, and the physics timestep (1/60 on every tier). **There are no shadow maps** — dynamic shadows were removed entirely (2026-08) because the depth-map pass was too costly for the visual payoff; `Lights.jsx` is a static fixed-direction warm sun + fills, and depth cues come from flat color contrast and fog (DESIGN.md §6). Don't reintroduce `castShadow`/`receiveShadow`/`<Canvas shadows>` without revisiting that decision. There's a WebGL context-lost overlay wired in `App.jsx`.

**Resolution is a pixel budget, not a DPR cap** (`resolveDpr`, tier 0 only — tiers 1/2 keep the old `dpr: [min,max]` clamp and are unchanged). A fill-rate-bound scene pays for *shaded pixels*; dpr is only the multiplier, so the same "dpr 1" that is honest on a 1× laptop rendered a 3× phone at a ninth of its screen resolution. `pixelBudget` (1.2 MP) ÷ viewport area gives the affordable dpr, clamped into `dpr` and never above the device's own — so a phone lands near 1.9 and a tablet near 1.1, both at the same total cost. It depends on viewport *area*, so `useRenderDpr` in `App.jsx` re-asks on resize/orientationchange; R3F's array form can't express this (it only clamps `window.devicePixelRatio`, which never changes on rotation). At tier 0 the watchdog sheds **resolution** (`SCALE_STEPS`) before declaring `struggling` — there is no simpler world below tier 0, and softening the picture beats deleting more of the world. The floor of that ladder is still ~2× sharper than the old flat `dpr: [1,1]`.

`antialias` is on **everywhere, phones included** (a WebGL context attribute, fixed at Canvas mount, so it can't be tier-driven). It used to be `!isMobile`, which was backwards: mobile GPUs are tile-based deferred renderers and resolve MSAA in on-chip tile memory, making it far cheaper there than on a desktop immediate-mode GPU.

`backdrop-filter` over a **live** canvas is a per-frame compositor readback, not a paint. Four blurred panels sit on screen the whole time you drive, so `App.jsx` adds a `.flat-hud` class (`isMobile && gameStarted`) that neutralises every `backdrop-filter` while the world is rendering; the panels already sit on 75–92% opaque grounds. The start screen keeps its blur — the canvas behind it is `frameloop="demand"` and not repainting. Don't reintroduce blur into the in-game HUD without that gate.

### Other pieces

- `Scene.jsx` composes everything 3D inside `<Physics>`; `World`/`Trees`/`EnvironmentModels` are the static world (instanced/capped by tier), `Zones.jsx` fires store actions on proximity, `AchievementSystem` watches store state and toasts unlocks (persisted in localStorage `achievedIds`/`visitedZones`).
- `Bowling.jsx` — SW quadrant mini-game: the car pushes a big dynamic ball into 10 pins on a wooden lane flanked by fixed bumper rails, with a clickable in-world ↻ RESTART sign (R3F pointer events, works as tap on mobile). Pin/ball/spacing dimensions are folio-2025's actual `areas.glb` values scaled ~0.875 (its truck ≈ our car's size); pins deliberately tower over the car. Strike = all 10 pins tilted past ~60°, detected per-frame via each pin body's up-vector; writes `strikeCount` to the store.
- Track visuals (`Circuit.jsx` `TrackPath`/`StartFinish`): opaque asphalt ribbon, raised red/white kerbs + white dashed centerline (all baked into 2 merged vertex-colored draw calls), checkered start/finish strip and an overhead gantry aligned to the track tangent. Kerbs/dashes are visual only — no colliders.
- **The track palette lives in `src/data/track.js`** (`ASPHALT`, `KERB_COLORS`, `LINE_PAINT`, `ASPHALT_*_SHADE`), not in `Circuit.jsx`, because the ramps are painted from it too — `Circuit.jsx` owns how the colours are laid out, `track.js` owns what they are. Both ramp files (`Ramps.jsx`, `TrackObstacles.jsx`) import from it, so "the ramps match the track" is enforced by construction rather than by a hex string copied between three files. Ramp decks, kerb stripes and lip lines are baked as **vertex colours into one merged geometry per ramp**, so the open-world ramps are still a single instanced draw call for all six.
- **Ramp colliders are built from the bare deck, never from the merged visual geometry.** The kerb/lip paint sits on top of the deck; folding it into the hull would lift the collision surface a few centimetres above the surface the eye sees and the wheels would ride on nothing.
- **The world has no edge** (`EndlessDesert.jsx`). Past the built 400×400 world a 3×3 grid of dune tiles follows the car and rebuilds ahead of it; `duneHeight(x, z)` is a pure function of world position, so neighbouring tiles agree along their shared edge and a revisited tile is identical — no state, nothing to stream. Each tile carries a `HeightfieldCollider` on the same samples as its mesh. Nothing renders or collides while the car is inside the built world. The old boundary walls are gone and the ground collider reaches ±2000 so nothing shoved past the edge falls forever. Past 450 units `ReturnHome.jsx` offers a dismissible lift home (passive panel, never a modal).
- **The dunes are shaded by vertex colour, not by the light** (`shadeAt` in `EndlessDesert.jsx`). This is the non-obvious part and it will look redundant: the sand is over-exposed — fill and key put ~2.8× on every surface and `#ee8f42` pins red at 255 — so a ±10° slope moves the pixel by ~8 levels out of 255 and the dunes render as a flat plane. Measured, not assumed: at 60 units of relief (6× the current value) the frame still only spread 14 luma levels. The range was never in the geometry, it was gone in the render. So each vertex is coloured by its own slope against `SUN_POSITION`, the same way the track and ramps bake their colours. **Don't "simplify" this back to a flat `color` — the dunes disappear.**
- `RoadInstructions.jsx` — "USE ARROW KEYS TO EXPLORE" / "R RESET · M MUTE · TAB MAP · SHIFT BOOST" lying on the east arm of the crossroads as **dynamic bodies**, one per word, so the sentence teaching you to drive isn't the one thing bolted down. `Text3D` builds glyphs asynchronously, so there is no width to measure at layout time and `CHAR_W` is a deliberately generous estimate — too narrow overlaps the colliders and the solver throws the sentence across the road on load. The layout constants are also sized so both lines finish inside the arrival frame; that was verified by screenshot at 1440×900, not by arithmetic.
- **The car's wheels are real, added geometry** (`Vehicle.jsx`). `car-1.glb` is a single Draco mesh with its wheels *painted into the bodywork*, so there was nothing in the model to rotate. Four vertex-coloured alloys are laid over the painted ones: outer group steers, inner mesh rolls. Steering and ride height come from the vehicle controller (`wheelSteering`, `wheelSuspensionLength`); the roll angle does not. `VIS_LIFT` and `BODY_LIFT` move only what is *drawn* — never the collider, axles or suspension — so the visual wheel size is free to change without touching how the car drives.
- `src/audio.js` — Howler wrapper; shuffled playlist from `/public/sounds/bg*.mp3`, engine/brake/collision SFX, `toggleMusic()` for the M key and MusicPlayer UI. **Music Howls set `html5: true`** — do not remove it: Howler's default (`html5: false`) XHRs each track as an arraybuffer and runs `decodeAudioData` on the main thread at the moment the visitor clicks START.
- **Tyre-on-gravel is three layers, not one** (`initGravel`/`updateGravel`, driven from `Vehicle.jsx`'s roughness figure): a lowpassed noise *body*, a bandpassed *grit* bed reading the same buffer at an unrelated rate, and scheduled *stone* grains through six fixed bandpass+pan lanes. The grains are the point — a looping buffer has colour but no events, so no gain or filter setting will ever make a bed alone read as stones. Two things are load-bearing and non-obvious: each lane carries a **makeup gain** of `sqrt(nyquist / bandwidth)`, because a bandpass keeps only its own slice of a full-spectrum grain and without it the stones land back underneath the bed; and grain envelopes decay to `amp * 0.02`, **not to zero**, because an exponential ramp's rate is set by its ratio — running one to 0.0001 packs 60 dB into the grain's length and turns every stone into a 5 ms click. Keep the grain rate sparse (~14/s): denser and they overlap into another wash.
- localStorage keys in use: `hasCountedVisit`, `hasWhispered`, `visitedZones`, `achievedIds`, `circuitBestLapMsV2`.

- 2026-09-13 verification pass over the 2026-09-10 work, run in a real browser rather than reasoned about — and the desert failed it. The dunes were being generated, collided and drawn, and were **invisible**: measured on the framebuffer, a frame of open desert had a luminance standard deviation of **0.05 out of 255**. Two independent causes, both of which had to be measured to find.
  1. **The slope figure in the source comment was derived, not measured, and was ~3× optimistic.** Smoothstep value noise climbs by at most `1.5·A/L` over a lattice cell, so "4.5 units over a 110-unit wavelength" is not 11° — sampling every 2 units over a 400-unit patch, the steepest face anywhere was **3.3°**.
  2. **Even correct geometry would not have shown.** Raising the relief to 9.5° moved the frame's sd from 0.05 to 0.45, and at a deliberately absurd 60 units of relief the ground *still* only spread 14 luma levels. The sand is over-exposed — ambient+key+fill put ~2.8× on every surface and `#ee8f42` pins the red channel — so slope contrast is clipped away before it reaches a pixel. This is why the built world looks fine (dark asphalt, dark trees, and a *textured* ground plane) and only the flat-coloured sand is affected.
  The fix is vertex colours (`shadeAt`), the project's existing idiom, plus wavelengths the follow camera can actually frame — it sees ~48 units of sand, so a 110-unit dune could only ever be a gradient. After: ground luma across the frame spans ~108–182 where it spanned 149–155, at 60 FPS and 41 draw calls, with the car's wheel clearance constant across the taper (verified driving from inside the world out past the boundary).
  Also fixed, same pass: `RoadInstructions` claimed in its own comment that both lines finish inside the arrival frame and they did not — at 1440×900 "EXPLORE" arrived as "EX" and "SHIFT BOOST" was off the edge; every layout constant is scaled ~0.84 and both lines now end before x = 15.4. And `canvas { touch-action: none }` was documented here but had never actually been written — it is in `App.jsx` now.
  **Still open:** the dunes meet the built world's ground plane at a visible straight colour seam. The heights taper to zero correctly, but `GradientFloor`'s warm edge vignette was designed for a world that *ended* there, and against open desert it reads as a hard line. Fixing it means changing the built world's signature look, so it is left as a decision rather than a tidy-up.

- 2026-09-10 ramps repainted in track colours, and the gravel sound rebuilt. Both ramps (open-world wedges and the circuit's) were warm amber on orange sand — the one pairing in this palette with almost no contrast, so a ramp dissolved into the ground it stood on and you could not read its slope or its edges at any distance. Now the circuit's own asphalt, kerbs and lip paint. The gravel bed was measured off the running audio graph rather than guessed at: crest factor 3.54 (the crest of pure Gaussian noise — literally "this is static"), spectral centroid 2.1 kHz, and a **0.76 envelope self-similarity at exactly 1.00 s**, which is the 1.5 s buffer divided by its 1.5x playback rate — an audible loop. After: crest 6.81, centroid 4.4 kHz, self-similarity down to 0.61 and pushed out to 2.02 s, at slightly *lower* overall RMS — the energy moved from wash to events rather than the sound just getting louder.

- 2026-09-10 mobile fidelity pass — the phone build was pixelated and juddery for four compounding reasons, all of them in config rather than in the scene. (1) `dpr: [1,1]` on tier 0 rendered every phone at 1× regardless of its real density, so a 3× screen got a ninth of its pixels and the browser upscaled the difference — replaced by the pixel budget above (0.33 MP → 1.20 MP on an iPhone 14), with a resolution ladder underneath it so the raise is safe on weak hardware. (2) `antialias` was disabled on exactly the devices where MSAA is cheapest. (3) Fog far was 80 over a 400-unit world (desktop: 300), which bought nothing — three's fog is a per-fragment colour mix that culls no geometry, and `camera.far` is a fixed 600 for every tier — so it was pure visual loss; now 260. (4) `physicsStep: 1/30` under a 60 Hz render made the camera, which reads `body.translation()` raw, stair-step against a car mesh that rapier interpolates to render rate — and `controller.updateVehicle(dt)` runs once per *render* frame, so a mismatched step applied its forces twice per world step; now 1/60 like every other tier. Also: `.flat-hud` drops the in-game backdrop blurs on mobile, the canvas takes `touch-action: none`, and `overscroll-behavior: none` stops the rotated frame rubber-banding. **Desktop is untouched** — tier 2 still resolves to dpr 1.5.
